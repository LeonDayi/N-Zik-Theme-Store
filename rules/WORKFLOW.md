# Workflow

- Inspect the working tree and existing conventions before editing. Preserve unrelated changes.
- Use `main` as the published source for the app and catalog. Keep contribution labels, issue forms, roadmap routing and documentation aligned when changing automation.
- Review input from forks as untrusted. A privileged workflow must use trusted code from the base branch, validate paths and author IDs, and use the permissions it needs.
- Keep account blocks, report routing and moderation reasons consistent with the repository’s documented process. Use test content or mocks to check moderation.
- Report what was verified. Push only changes within the authorized scope.
